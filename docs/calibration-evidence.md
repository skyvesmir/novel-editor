# 較正と設計判断の根拠（開発用・配布skillには含めない）

配布ファイル（`novel-editor/`）から、開発の経緯と測定の記録をここへ移した。claude.ai で skill を読み込むたびに経緯まで読ませないためである（無料枠でも使える設計）。skill 側には「どの数値が較正済みか・暫定か」だけを残している。

著作権ルールに従い、ここには数値と手順のみを書く。作品本文の引用は書かない。作品名は測定対象の識別のためにだけ使う。

出典の凡例：**G** = Genspark 系統（2026-09-02〜09-22）、**Q** = Qwen 系統（2026-09-08〜09-16）、**共通** = 分岐前（forgens 取り込み時点、2026-08-26 まで）。詳細な一次記録は各系統の作業ログ（ローカルのみ・GitHub 非掲載）にある。

## 設計判断の記録

- **10点は使わない**（共通・2026-08-26）：段階評価の弁別は3〜5段が実用限界で、上端に段を足すと天井効果が出る。10点を較正できる作品が標本にない。
- **7軸の分割は妥当**（共通・2026-08-26）：42達成条件・8上限規則・5診断観点を、文献・商業作の実測・外部の技法体系の3源で照合し、抜けなし。
- **ご都合主義の範囲限定**（共通・2026-09-06）：1箇所で二軸に上限をかける規則が、3箇所で一軸の紋切り型より重すぎたため、クライマックスとその準備場面に限定した。
- **掲載形態が未確認のとき**（統合版・2026-09-29）：G は「三択を質問して止まる」、Q は「尋ねたうえで2として扱う」だった。無料枠では往復1回の重みが大きいので、「三択を示しつつ、同じ応答で2として採点し、3の場合の差を一行添える」に統合した。旧 #15 の実走では、Sonnet が「連載中」から選択肢1を除外して二択で尋ねる失敗が2回続いた（A1 FAIL）。統合版では、理由を添えれば除外してよいとした。
