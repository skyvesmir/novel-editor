## 2026-08-24 — 第一章実採点での発見（フィールドテスト）

『虚空に宿りゆく六炎』第一章（約5.5万バイト）で採点モードを実運用。判明した仕様上の論点：

1. **改善案数の算術矛盾**：rubric の Weaknesses は「各軸の最重要弱点に3件＋他1件」を要求し7軸で最低21件になる一方、evals #1 の assertion は「改善案総数10件以下」。両立不可能。要調整（例：「軸別は最大3件、ただし全体で10件キャップを優先」の順に明記）。
2. **才能・技術スコアの達成条件不在**：handoff-format が 才能/技術 を X/10 で要求するのに、score-anchors に対応する条件表が存在しない。「条件名の無い点数は点数ではない」という本スキル独自の規則と自己矛盾。
3. **長文原稿の手順欠落**：5万字超原稿での引用台帳の作り方等が未規定。
4. **牽引力の暫定表示**：第1章では回収判定が必ず保留になるため、「7（回収未検証）」のような表記規約があると誤解がない。
5. 著者からの反論（サガ内心部の改行分離は意図的か）への対応は eval #4 の手順どおり：新しい引用なしに点数は動かさず、未充足条件と具体変更を再提示。
6. **派生発見（仕様ギャップ）**：著者が「意図的な視点ズーム（ペレナ場面と同種のカット）」と主張したケース。prose-diagnostics / score-anchors は「マーカー付き場面カット（区切り記号＋時刻＋場所ヘッダで枠を張り直す）」と「無印の視線リーク（進行中の場面内で語り手が滑る）」を区別していない。Step 2 の「意図的技巧」反論を採否するときの判定材料（効果が本文上で独立に観測可能か／装置の標識があるか／作品内で体系化されているか）を文章軸に1項目追加する価値がある。

## 2026-08-24 — 監査ドライラン #1 実行（出涸らし皇子）と仕様改善

**実行内容**：完結765話・約277万字（PDF抽出テキスト、エラー0件）を対象に audit-mode.md の手順を実走。Layer 0 台帳プロトタイプ構築（人物レジスタ上位25名・17部の部境界を前書き/後書きで全裏取り・弧骨格プロファイル）、機械走査（キーワード頻度・尾フック検出・デシル分析）、極小標本精読（数千字＝全体の0.2%未満）。

**発見した仕様ギャップ → 即日修正**：

1. **機械走査と精読の線引きが未定義だった**。走査は「兆候収集」に過ぎず判定根拠にならないにもかかわらず、初回実行では走査結果から条件判定まで飛躍してしまった。→ audit-mode.md に「Machine scanning vs. close reading」節を新設：①走査はシグナルのみ・判定は不可、②判定には反証候補込みで2〜4話/弧境界の全文脈精読が必要、③**精読量の出力明示を必須化**（「精読約X字／全体Y万字のZ%」）。宣言できない監査は監査ではない。
2. **保留表記が監査出力で未規定だった**。→ Report 手順に `点数:7(回収未検証)` 形式の暫定マーク運用を明記。

**作品側の暫定シグナル（正式判定ではない・GitHub上では詳細を記録しない）**：主筋循環・リズム変動・正体開示の長期回収に前向きシグナル、感情設計のテーマ一致に保留シグナル。詳細はローカル作業ファイルのみ。

**教訓**：evals #13 の設計自体は機能した（台帳先行・条件限定・標本宣言は守れた）が、「判定に必要な精読量」の下限が未定義だとエージェント（自分含む）が走査で満足してしまう。線引き条項はこの失敗を受けての追加。

検証：アーカイブ9ファイル再構築、ZIP整合性 OK、ツリーとの一致確認済み。
